### 4. 实现思路（约 15 行 + 1 张图）
- 架构图（可用 ASCII 或 Mermaid，取自 [04-architecture.md](04-architecture.md) §1）。
- 一次生成的流程：PM（结构化 JSON）→ 工程师（模板配置 / 自由生成 / 补丁）→ 测试员（静态检查 + 浏览器运行时检查 → 自动修复 ≤4 轮 → 回退）。

- 编排方式：Vercel AI SDK（`generateObject` + zod、`streamText`）+ 手写 TypeScript 状态机；每一步写入 messages 表驱动 UI 卡片，刷新可完整恢复。

### 5. 关键取舍（最重要的一节，约 20 行）
每条写成"选择 → 理由 → 代价"：
1. **低成本模型下的质量策略**（单独一段，重点）：只用 DeepSeek Flash，用四层工程手段兜底：
   - 模板优先：8 个精修模板，模型只输出 JSON 配置 → 解决"低成本模型写长代码不稳定"，代价是多样性受限。
   - 多步短输出：PM 和配置都是小 JSON，zod 校验 + 自动重试 → 格式错误可自动恢复。
   - 自动修复闭环：静态检查 + 运行时报错回传，最多 4 轮，失败回退 → 用户永远不会停在一个坏版本上。
   - 补丁式修改：SEARCH/REPLACE，失败才整页重写 → 输出更短更快，不丢已有内容。
   - 结论："在成本约束下，用工程手段换稳定性，比依赖模型能力更可控。"附实际成本数据（`npm run usage` 输出：平均每次生成的 token 与费用）。
2. 单文件 HTML vs 多文件工程（WebContainer）。
3. 增量编辑 vs 整页重写。
4. 匿名访客 ID + 恢复码 vs 登录。
5. 沙箱安全边界：无 `allow-same-origin`，localStorage 通过 postMessage 垫片持久化到父页面。
6. 自有服务器 + Docker Compose vs Serverless：流式生成不受函数时长限制。
7. SQLite vs Postgres：单机零运维，Drizzle 迁移到 Postgres 改动很小。
8. 手写状态机 vs LangGraph / Mastra：三步流程手写更透明；步骤变多或需要断点续跑时再迁移。

### 6. 后续规划（按优先级，每条一句理由）
1. WebContainer 多文件 React 工程（突破单文件规模上限）。
2. 扩充模板库，把高质量的生成结果沉淀为新模板（数据飞轮）。
3. 点选编辑：在预览中点元素直接提修改。
4. 竞速模式：同一需求多模型并行，用户择优。
5. 生成应用自带后端与数据库（类 Atoms Cloud）。
6. 迁移到 LangGraph 实现可恢复的长流程；HTTPS 与域名。
