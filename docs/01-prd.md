# 01 · 产品需求文档（PRD）

> 本文档定义"做什么"和"做到什么程度算完成"。实现细节见后续文档。所有验收标准都必须可以在浏览器里手动或用 Playwright 验证。

## 1. 背景与目标

这是 DeepWisdom（ROOT）AI Native 全栈岗位的笔试作品，产品形态参考 atoms.dev：用户用自然语言描述想要的应用，一支可见的 AI 智能体团队把需求整理成方案、写出代码，生成结果在页面里实时预览，并且可以继续对话修改。

评审维度：完成度、工程思维、用户体验、创新性、可交付性。因此本项目的目标排序是：

1. **主流程稳定**：演示时任何一步都不能卡死或白屏。宁可功能少，不可出错。
2. **可交付**：公开可访问的在线链接（自有云服务器，IP 直连）、公开 GitHub 仓库、清晰的 README。
3. **体验像产品**：有加载态、错误态、空状态，交互流畅，中文文案统一。
4. **有一个记忆点**：可见的多智能体团队 + 自动测试修复闭环。

## 2. 产品名称与定位

- 产品名：**Atoms Demo**（页面标题、Logo 文字统一用这个）。
- 一句话：用一句话描述你的应用，AI 团队几十秒内交付一个可交互、可分享的单页应用。
- 生成物：**单个自包含 HTML 文件**（内含 Tailwind、原生 JavaScript，数据存 localStorage）。不生成多文件工程，不生成后端。

## 3. 用户与场景

- 唯一用户类型：匿名访客（评审官、HR、任何拿到链接的人）。无注册、无登录。
- 典型场景：
  - 评审官打开链接，点一个示例提示词，看着三个智能体接力工作，30 秒内看到一个能用的待办应用。
  - 评审官输入"帮我做一个记录健身的应用，有每周统计图"，得到可用应用后说"把主色改成绿色，再加一个备注字段"，应用被增量修改。
  - 评审官把作品分享链接发给同事，同事无需任何操作即可全屏打开使用。
  - 评审官刷新页面、关闭浏览器再打开，项目、对话和每个版本都还在。

## 4. 范围

### 4.1 必须交付（P0）

| 编号 | 功能 | 说明 |
|---|---|---|
| F1 | 首页需求输入 | 大输入框 + 4 个示例提示词 + "我的项目"列表 |
| F2 | 创建项目并进入工作台 | 提交需求后创建项目，跳转到工作台并自动开始生成 |
| F3 | 工作台双栏布局 | 左侧对话，右侧"预览 / 代码"两个 Tab；桌面端可拖拽分栏，手机端上下切换 |
| F4 | 多智能体流式生成 | 产品经理 → 工程师 → 测试员依次出现活动卡片，状态实时更新，代码流式出现 |
| F5 | 沙箱实时预览 | 生成的应用在 iframe 沙箱中运行，可点击、可输入、数据可持久化，不影响主站 |
| F6 | 追问修改 | 在已有应用基础上继续对话修改，优先改配置或打补丁，而不是整页重写 |
| F7 | 数据持久化 | 项目、消息、每一版代码存入 SQLite；刷新、重开浏览器完整恢复 |
| F8 | 我的项目 | 列出当前访客的项目，可打开、重命名、删除 |
| F9 | 错误与加载状态 | 模型超时、输出不合法、网络断开、限流时都有明确提示和"重试"按钮 |
| F10 | 防滥用 | 按访客和 IP 限流，全站每日上限；超限时友好提示 |

### 4.2 延展能力（P1，必须至少完成 E1 和 E2）

| 编号 | 功能 | 说明 |
|---|---|---|
| E1 | 可见的智能体团队 + 自动修复闭环 | 测试员在预览加载后检查运行时报错，自动让工程师修复，最多 2 轮，仍失败则回退到上一个可用版本 |
| E2 | 版本时间线与回滚 | 每次交付是一个带名字的版本，可预览任意旧版并一键恢复 |
| E3 | 公开分享链接 | 一键公开，`/share/[projectId]` 全屏展示生成的应用，无需登录 |
| E4 | 下载 HTML | 导出单文件，双击即可在本地浏览器运行 |
| E5 | 手动"让智能体修复" | 用户操作过程中出现的报错，显示"让测试员修复"按钮 |
| E6 | 恢复码（换设备找回） | 显示访客恢复码，在另一台设备输入后可看到同一批项目 |

### 4.3 可选（P2，时间有富余才做，按顺序）

| 编号 | 功能 |
|---|---|
| X1 | Remix：在分享页点"复制一份来改"，复制为自己的新项目 |
| X2 | 预览设备切换（桌面 / 手机宽度） |
| X3 | 代码 Tab 可编辑并保存为新版本 |

### 4.4 明确不做

注册登录、多文件工程、生成应用的后端与数据库、自定义域名、HTTPS 证书（无域名）、支付、多模型竞速、图片上传、国际化切换（主站只做中文）。

## 5. 用户故事与验收标准

每条验收标准（AC）都必须在 [13-test-acceptance.md](13-test-acceptance.md) 中有对应检查项。

### US-1 首页快速开始（F1、F2）

作为访客，我想在首页一句话描述需求或点一个示例，就能开始生成。

- AC-1.1 首页有多行输入框，占位文案"描述你想要的应用，例如：一个记录每天喝水量的打卡应用"。`Enter` 提交，`Shift+Enter` 换行，输入为空时提交按钮禁用。
- AC-1.2 输入框下方有 4 个示例提示词卡片（内容见 [02-ux-ui-spec.md](02-ux-ui-spec.md) §4.1），点击即直接提交。
- AC-1.3 提交后 1 秒内跳转到 `/p/[id]`，工作台自动开始生成，无需再次点击。
- AC-1.4 输入超过 2000 字时禁止提交并提示"需求描述请控制在 2000 字以内"。
- AC-1.5 首页"我的项目"区域展示当前访客的项目卡片（标题、最后更新时间、缩略状态），按更新时间倒序；没有项目时显示空状态文案。

### US-2 看着 AI 团队工作（F4、E1）

作为访客，我想看到不同角色的智能体分工协作，知道它们在做什么。

- AC-2.1 生成开始后 2 秒内，左侧出现"Mia · 产品经理"活动卡片，状态为"分析需求中"。
- AC-2.2 产品经理完成后，卡片展示：应用名称、选择的模板（或"自由生成"）、3 到 6 条功能要点。
- AC-2.3 随后出现"Leo · 工程师"卡片。模板路径显示"正在填写应用配置"；自由生成路径在代码 Tab 中逐段流式出现 HTML。
- AC-2.4 工程师完成后预览自动刷新，出现"Iris · 测试员"卡片，状态"检查运行情况"，3 秒内给出结果："通过"或"发现 N 个问题，正在修复（第 k/2 轮）"。
- AC-2.5 自动修复成功后生成新版本，测试员卡片显示"已修复"。2 轮都失败时自动回退到上一个通过检查的版本，并显示"修复失败，已回退到 vX"；若没有可回退的版本，显示错误详情和"重新生成"按钮。
- AC-2.6 每张卡片有角色头像（彩色圆形 + 首字母）、角色名、状态图标（进行中转圈 / 完成对勾 / 失败叉号）、耗时。

### US-3 预览与使用生成的应用（F5）

- AC-3.1 预览区用 `<iframe sandbox>` 渲染，sandbox 属性**不含** `allow-same-origin`。
- AC-3.2 生成的应用中按钮可点击、表单可输入、弹窗可用。
- AC-3.3 应用写入的数据（localStorage）在刷新工作台后仍在；工具栏有"重置应用数据"按钮可清空。
- AC-3.4 生成的应用中的报错不会让主站报错或白屏。
- AC-3.5 预览工具栏有"刷新预览""在新标签打开（分享页）""下载"按钮。

### US-4 继续对话修改（F6）

- AC-4.1 生成完成后，底部输入框可继续输入修改要求；生成进行中输入框禁用并显示"团队正在工作…"和"停止"按钮。
- AC-4.2 对模板应用说"把主色改成绿色""加一个备注字段""标题改成 XX"，产品经理判断为"修改配置"，工程师只输出新配置，原有数据和其余内容不变。
- AC-4.3 提出模板配置做不到的修改（如"加一个导出 CSV 按钮"），走"代码补丁"路径，只改动相关片段。
- AC-4.4 补丁无法应用时自动重试 1 次；仍失败则自动改为整页重写，用户只看到最终结果和一句说明。
- AC-4.5 提出完全不同的应用（如当前是待办，说"改成一个贪吃蛇游戏"），走"重新生成"路径。
- AC-4.6 每次修改都产生新版本，版本号递增。

### US-5 版本时间线与回滚（E2）

- AC-5.1 每次成功交付在对话流中插入一张版本卡片：`v{seq}` + 版本名（≤16 字）+ 时间 + 来源标签（template→模板、config_edit→配置、free→自由生成、patch→补丁、fix→修复、manual→手动）。
- AC-5.2 顶栏有版本下拉，按时间倒序列出所有版本，当前版本有"当前"标记，未通过检查的版本有红色"有问题"标记。
- AC-5.3 点击任意旧版本卡片进入"查看模式"：预览显示该版本，顶部出现黄色提示条"正在查看 v2（只读）· 恢复此版本 · 返回当前"。
- AC-5.4 点击"恢复此版本"后，该版本成为当前版本，对话流插入一条系统消息"已恢复到 v2"，后续修改基于它进行。恢复不删除任何版本。

### US-6 分享与下载（E3、E4）

- AC-6.1 顶栏"分享"按钮打开弹窗：开关"公开访问"，开启后显示链接 `http://<host>/share/<projectId>` 和"复制链接"按钮。
- AC-6.2 复制在非 HTTPS 下可能失败，失败时自动选中链接文本并提示"请手动复制"。
- AC-6.3 未公开的项目访问分享页返回 404 页面"这个应用不存在或未公开"。
- AC-6.4 分享页全屏展示当前版本，右下角有小徽标"由 Atoms Demo 生成"，点击回到首页。支持 `?v=<seq>` 查看指定版本。
- AC-6.5 下载得到 `<标题>.html`，双击用浏览器打开可正常运行，数据存在本地 localStorage。

### US-7 持久化与项目管理（F7、F8、E6）

- AC-7.1 首次访问自动分配匿名访客 ID（cookie，有效期 1 年），无需任何操作。
- AC-7.2 刷新工作台，对话、所有智能体卡片、版本、当前预览完整恢复。
- AC-7.3 项目可重命名（顶栏标题点击即编辑，回车保存）和删除（二次确认弹窗，删除后回首页）。
- AC-7.4 只能看到和操作自己的项目；访问他人项目的工作台返回 404。
- AC-7.5 首页右上角"恢复码"菜单显示当前恢复码（即访客 ID 的展示形式），可输入另一个恢复码切换身份。

### US-8 出错时不慌（F9、F10）

- AC-8.1 模型调用失败或超时：当前智能体卡片变红，显示原因（中文）和"重试"按钮，重试会重新执行本轮需求。
- AC-8.2 生成过程中网络断开：显示"连接中断"，刷新后看到已保存的进度（未完成的一轮不产生版本）。
- AC-8.3 同一项目同时只能有一个生成任务，重复提交返回提示"团队正在处理上一个需求"。
- AC-8.4 超出限流：输入框上方显示"今日生成次数已用完（每个访客每天 N 次），明天再来吧"。
- AC-8.5 点击"停止"后立即中断，当前一轮不产生版本，卡片显示"已停止"。

## 6. 非功能需求

| 类别 | 要求 |
|---|---|
| 性能 | 模板路径首个版本 P50 ≤ 20 秒；自由生成 P50 ≤ 60 秒；工作台首屏 ≤ 2 秒（服务器同地域） |
| 稳定 | 8 个示例类需求（每个模板 1 个）连续跑 3 遍，成功率 ≥ 95%（成功 = 最终有通过检查的版本） |
| 安全 | 生成代码只在无 same-origin 的沙箱中运行；API Key 只在服务端；所有接口校验访客归属 |
| 成本 | 只用 DeepSeek Flash；单次生成（含修复）平均 token 成本 < $0.01；有每日全站上限 |
| 兼容 | 最新版 Chrome、Edge、Safari、Firefox；手机宽度 375px 可用 |
| 可部署 | `docker compose up -d --build` 一条命令启动；无外部数据库依赖 |
| 可观测 | 每次模型调用记录耗时、token、结果到 `llm_calls` 表；服务端日志为单行 JSON |

## 7. 成功标准（交付前自检）

1. [13-test-acceptance.md](13-test-acceptance.md) 中所有 P0、E1、E2 检查项通过。
2. 在线链接用无痕窗口和手机各完整跑通一遍。
3. README 能让陌生人 5 分钟内在本地跑起来。
